# Ticket Radar Android v0.1

这是一个手机独立运行的 Android 原生版本，不需要电脑、安卓模拟器或 ADB 常驻。

## 工作方式

它使用 Android 系统的 **无障碍服务（AccessibilityService）** 读取大麦 App（包名 `cn.damai`）当前前台页面中系统可访问的文字和控件。

开启“武装监控”后：

1. 如果看到目标票价，并且对应控件处于可点击状态，会执行一次普通 `ACTION_CLICK`。
2. 如果还停留在演出详情页，可选地点击“立即购买 / 选座购买 / 立即预订”等正常入口。
3. 如果出现“验证码 / 滑块 / 安全验证 / 人机验证 / 排队 / 确认订单 / 支付”等文字，会立即取消武装并提醒人工接管。
4. 不破解验证码，不绕过排队/风控，不自动确认订单，不自动支付。

## 使用

1. 安装 APK。
2. 打开 Ticket Radar。
3. 输入目标票价，例如：`1580,1280,980,780`，越靠前优先级越高。
4. 点“打开无障碍设置”，找到 **Ticket Radar 页面监控** 并开启。
5. 回到 Ticket Radar，点“保存并开始监控”。
6. 大麦打开后进入邓紫棋目标场次页面，让 App 保持前台。

> Android 会对无障碍权限显示明显警告，这是系统对所有此类 App 的正常提示。此项目代码没有网络权限，也不会上传页面内容。

## 诊断

首页下方会显示“最近一次从大麦读取到的可访问文字”。

如果票档明明在屏幕上，但诊断区完全没有对应价格/按钮，说明该版本大麦可能用 Canvas、不可访问 WebView 或其他方式渲染，当前无障碍方案无法直接读取。把诊断文字发给开发者，可以针对实际 UI 继续适配。

## 生成 APK（GitHub Actions）

项目已包含 `.github/workflows/build-apk.yml`。

把整个目录推到 GitHub 后：

1. 打开仓库的 **Actions**。
2. 运行 **Build Android APK**。
3. 构建完成后下载 Artifact：`TicketRadar-debug-apk`。
4. 其中的 `app-debug.apk` 可以直接安装测试。

这是 debug APK，Android 可能提示“未知来源”，需要允许浏览器/文件管理器安装未知应用。

## 本地 Android Studio

直接用 Android Studio 打开项目，等待 Gradle 同步后运行或选择：

`Build > Build APK(s)`

## 当前限制

- 只有大麦当前页面处于前台时才扫描。
- Android 可能在省电模式下限制后台行为，因此建议测试时关闭 Ticket Radar 的电池优化。
- 不使用坐标盲点，而是只点击系统报告为“可点击”的正常控件；因此比纯坐标脚本更稳，但也依赖大麦是否向 Accessibility 暴露这些控件。
